Let's do some final touches to the @analyze-dogs.py:
 - add a --mode argument to select between 
  - analyze - the current behaviour (produce images with bounding boxes and confidence), with a slight modification - scale down the images to a maximum size (720x720) keep the aspect ratio, so the output images are not too big, but the bounding boxes are still visible and accurate (the confidence should be the same as before, just the image is smaller)
  - dry-run - just print the detected classes and confidence to the console, 
  - tag-images - add tags (IPTC keywords) to the images based on the detected classes (e.g. "Raff", "Saga", "Cakun") and save them in place of the original images (just add the IPTC metadata, do not change the image content)
    be careful here to keep the original create/modify dates of the images when saving them back
 - all modes can at the and provide some summary statistics (e.g. number of images processed, number of detections, average confidence, etc.)    
 - add a --filter argument (glob) to select only a subset of images to process (e.g. --filter "2023-12-*.jpg" to process only images from December 2023)
 - add a --valid-tags argument to specify which classes should be considered valid for tagging (e.g. --valid-tags "Raff,Saga") - only these classes will be used for tagging (this should apply to all modes, but especially to the tag-images mode)
 - the logic around the tag-images mode can be taken from the local file @tag-photos-gemini.py, which already has some code to add IPTC keywords to images based on detected classes. You can reuse that code and adapt it to work with the output of the detection model.
